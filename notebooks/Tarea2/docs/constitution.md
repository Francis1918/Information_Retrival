# Constitución: recuperación de información, búsqueda secuencial vs índice invertido

Principios innegociables (etapa 1 del SDD). Cada uno es verificable: se cumple o no se cumple.

1. **Simplicidad.** No debe construirse stemming, stopwords, ranking, consultas de frase, parser de consultas, librerías de búsqueda, persistencia del índice, paralelismo ni copia o extracción de datos. No debe existir ningún archivo de código (`.py`) ni de salida fuera de `02_booleansearch.ipynb`. Solo deben usarse nltk, numpy, matplotlib, psutil, ipykernel y la biblioteca estándar de Python 3.13.
2. **Autoridad de spec.** La especificación (el enunciado del notebook y el contexto de este proyecto) debe ser la fuente de verdad y el código debe ajustarse a ella. Ante una discrepancia, el código debe corregirse; la spec no debe cambiar sin aprobación humana.
3. **Desacoplamiento lógica/IO.** La normalización y tokenización, la búsqueda secuencial (dos lazos `for` anidados), el índice, la fusión AND/OR/NOT de listas ordenadas y el ajuste lineal t = an + b con R² deben vivir en funciones que reciben datos en memoria y no deben leer disco ni imprimir. La lectura de `pg<N>.txt`, la medición de memoria y disco y las gráficas deben estar en celdas separadas. La ruta de datos debe definirse en una única variable de la celda de configuración.
4. **Política de tests.** No debe usarse un framework de pruebas; la verificación debe hacerse con `assert` dentro del notebook. Ambos métodos deben devolver exactamente los mismos ids antes de comparar cualquier tiempo. Debe comprobarse que cada carpeta contenga un único `pg<N>.txt`, registrando las que no cumplan. Las mediciones deben usar calentamiento y 30 ejecuciones, sin incluir carga ni tokenización.
5. **Persistencia.** No debe persistirse nada: índice, resultados y gráficas deben existir solo en memoria y en las salidas del notebook. La carpeta de datos (una carpeta numérica por libro, fuera del repositorio) debe tratarse como solo lectura; no debe escribirse en ella ni dentro del repositorio. El id de documento debe ser el número de carpeta y los subconjuntos deben ordenarse por ese número como entero.
6. **Idioma.** El código, los comentarios, las celdas markdown y los textos mostrados deben estar en español. Los comentarios deben explicar el porqué técnico y el razonamiento largo debe ir en celdas markdown.
